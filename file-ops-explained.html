① 一句话理解

给 AI 一把只在工作区里生效的原子笔：
  • 边界围栏（路径逃逸检测）——笔尖永远戳不出工作区，目录穿越、符号链接逃逸都拦住。
  • 橡皮擦（Undo 历史）——写之前先拍快照，写错了能一键还原。
  • 不写崩（原子写入）——索引文件用"临时文件 + 重命名"落盘，崩溃也不会留半截。
  • 顺序闸（并发读写）——Agent 串行写、Watcher 只读轮询，元数据用锁保护。

② 四道安全闸门

闸门 1 · 边界

路径逃逸检测

词法 Clean/Rel + 符号链接 EvalSymlinks 双校验，读写始终限定在工作区内。
闸门 2 · 回退

Undo 历史

写前快照压入栈（保留最近 100 条），支持一键回退到任意修改前。
闸门 3 · 落盘

原子写入

元数据用 tmp + rename 原子替换，避免半截写入与读写竞争。
闸门 4 · 并发

并发读写

元数据 Mutex 全互斥；业务文件靠 Agent 串行 + Watcher 只读。

⑧ 面试能怎么讲

主线叙事：让 AI Agent 落地写代码是个高危动作，我用四层机制把它变安全——边界围栏防写出工作区、Undo 快照能回退、原子落盘不写崩索引、串行 + 锁保证并发正确。

可能追问怎么答（体现 trade-off）
业务文件为什么不用 tmp+rename 原子写？Agent 单 loop 串行执行，write 无并发竞争；且 Undo 已存写前快照作回退安全网，原子写收益低、替换成本高 → 用 Undo 替代。
并发怎么保证？元数据 Mutex 全互斥；业务文件靠串行执行 + Watcher 只读轮询，无文件级锁。
符号链接怎么检测的？EvalSymlinks 解析真实路径后对真实 root 再算 Rel，看是否仍在 root 内；新文件则校验最近已存在父目录。
崩溃时索引会坏吗？不会。先写 .tmp 再 rename，rename 在同类文件系统上是原子操作。

诚实点：业务文件写入本身非原子（os.WriteFile 直接覆盖）——面试被问"原子性"要能承认并用 Undo 兜底解释，这反而是加分项。
